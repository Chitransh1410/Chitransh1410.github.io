04 — Projects

Four stories, told properly

Each project is a short film — the problem, the decision and what happened next. They start as you scroll.

Raw Material Dashboard

Highest impact

Raw material stock lived in five different places — nobody could see total cover in one view, so reordering was reactive. I built a dashboard that consolidated it: what we hold, what's committed, and how many weeks of cover remain per material.

In the board meeting, the number nobody could see before made the call obvious. We released the order early and secured roughly three months of cover. The next morning, the route was gone.

Regional stock ran down. Ours didn't — and we stayed among the few still supplying finished goods across the UAE. What began as a stock report became a continuity decision.

Customer Churn Prediction

Public rebuild in progress

Customers don't announce that they're leaving — revenue just quietly leaks. The first model scored 91% accuracy by predicting that nobody would churn, which is excellent on paper and useless in practice.

So I tuned for F1 and chose the decision threshold deliberately, trading precision for the recall that matters when missing an at-risk account costs more than one unnecessary call.

F1 of 0.73 — a ranked list the retention team could actually work through, rather than a number that flattered the model.

Executive Dashboard Redesign

Public rebuild in progress

The reports were accurate and unreadable — fourteen columns the CEO had to decode before he could decide anything. He said so plainly, and he was right.

I rebuilt them KPI-first: the four numbers that drive the weekly decision at the top, trend underneath, detail one click away. Same data model, same DAX — a different answer to “what is this page for?”

Live Stock API for Power BI

Live on GitHub

The report ran on a CSV someone exported by hand, so it was always out of date. Power BI can refresh against a web endpoint — there just wasn't one for a custom watchlist.

So I built it: a Flask API that fetches each ticker, flattens the fields Power BI needs into one row per company, and serves flat JSON. Power Query reads it directly — expand, set types, schedule the refresh.

A small piece of data engineering standing between a dashboard and the thing it's supposed to be reporting on.
